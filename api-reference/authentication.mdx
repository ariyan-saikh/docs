---
title: "Authentication"
description: "Authenticate every request with an UnPay API key."
---

The UnPay Public API uses **API key** authentication. Every request must present
a valid secret key, either as a bearer token or in the `x-api-key` header.

## API keys

Keys are created in the [UnPay Dashboard](https://app.unpay.in) under
**Developers → API Keys**. A key looks like:

```
agl_1a2b3c4d5e6f7g8h9i0j...
```

The full secret is displayed **once** at creation and stored only as a bcrypt
hash — UnPay can never show it again. If you lose it, rotate the key.

Each key carries:

- a set of [**scopes**](/api-reference/scopes) (per-resource read/write),
- a [**rate limit**](/api-reference/rate-limits) (requests per minute),
- an optional **IP allowlist**,
- an optional [**signed-requests**](/api-reference/request-signing) requirement.

## Sending the key

Use either header. Bearer is recommended.

<CodeGroup>
```bash Authorization header
curl https://api.unpay.co/v1/me \
  -H "Authorization: Bearer agl_your_secret_key"
```

```bash x-api-key header
curl https://api.unpay.co/v1/me \
  -H "x-api-key: agl_your_secret_key"
```
</CodeGroup>

A successful call to `GET /me` confirms the key works and returns the owning
account:

```json
{
  "id": "usr_...",
  "email": "you@company.com",
  "name": "Acme Payments",
  "credits": 12500,
  "planType": "growth"
}
```

## Failure responses

| Status | Meaning |
|---|---|
| `401` | Missing, malformed, or invalid key (`Missing API key…` / `Invalid API key.`). |
| `403` | Disabled or expired key, missing scope, IP not allowlisted, or a non-HTTPS request. |
| `429` | Rate limit exceeded for the key. |

```json
{
  "error": "Missing API key. Provide it via 'Authorization: Bearer agl_...' or the 'x-api-key' header."
}
```

<Warning>
  Treat keys like passwords. Store them in a secrets manager, scope them
  narrowly, use separate keys per integration, and rotate on suspected
  exposure. Repeated invalid-key attempts from an IP are throttled.
</Warning>
