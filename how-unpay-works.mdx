UnPay is a single REST API in front of two products. This page explains the
concepts you'll use across both.

## One API, scoped keys

All requests go to:

```
https://api.unpay.co/v1
```

You authenticate with an [API key](/api-reference/authentication) that carries a
fixed set of [scopes](/api-reference/scopes). A key can read/write only the
resources its scopes allow, is optionally locked to an IP allowlist, and can
optionally require [signed requests](/api-reference/request-signing). Every query
is constrained to the key owner, so one account can never see another's data.

## Payouts: wallets and money movement

<Steps>
  <Step title="Fund an account">
    Money moves out of an **account**. An account exposes a balance, per-mode
    availability (IMPS/NEFT/RTGS/UPI), and a `balanceSource` of either `ledger`
    or `bank` (Connected Banking). List them with `GET /payouts/accounts`.
  </Step>
  <Step title="Send a payout">
    `POST /payouts` transfers to a bank account or UPI ID — either a manual
    beneficiary or a saved `payoutAccountId`. Money movement **requires an
    [idempotency key](/api-reference/idempotency)** so retries never double-pay.
  </Step>
  <Step title="Track status">
    A payout moves through `queued → processing → completed` (or `failed` /
    `returned` / `cancelled`). Poll `GET /payouts/{id}` or, better, subscribe to
    webhooks.
  </Step>
</Steps>

## AI Calling: agents, campaigns, calls

<Steps>
  <Step title="Create an agent">
    An **agent** defines the AI voice, language, prompt and behaviour. `flow`
    agents run outbound campaigns; `incoming` agents answer inbound calls.
  </Step>
  <Step title="Launch a campaign">
    A **campaign** pairs an agent with a caller-ID number and a list of
    **contacts**, with optional scheduling windows and retry rules.
  </Step>
  <Step title="Read the results">
    Each dial produces a **call** record with status, duration, transcript,
    recording URL and an AI summary. Fetch them via `GET /calls`.
  </Step>
</Steps>

Voice minutes are metered in **credits** — check your balance any time with
`GET /me`.

## Events over webhooks

Instead of polling, register a [webhook](/guides/verify-webhooks) to receive
signed, replay-protected deliveries for payout, call and campaign events such as
`payout.completed`, `call.completed` and `campaign.completed`.

## Built for money movement

- **Idempotency** on every payout — safe retries by design.
- **Cluster-wide rate limits** per key — see [Rate limits](/api-reference/rate-limits).
- **Secrets encrypted at rest** — signing secrets and webhook credentials are
  never stored or returned in plaintext.
- **Stable error codes** — branch on `code`, see [Errors](/api-reference/errors).
